# n8n + Ollama (Gemma 3) — Local Docker Stack with nginx Security

A self-contained local stack:

- **n8n** — workflow automation, only reachable through nginx
- **ollama** — running `gemma3:4b`, only reachable from n8n (not exposed to host)
- **nginx** — reverse proxy in front of n8n: TLS, HTTP→HTTPS redirect, security
  headers, rate limiting, and an extra basic-auth layer on top of n8n's own login

```
Browser ──HTTPS──▶ nginx ──HTTP──▶ n8n ──HTTP──▶ ollama (Gemma 3)
                (only exposed        (internal        (internal
                 container)           network)          network)
```

## Files

```
n8n-ollama-stack/

├── .env.example
```

## 1. First-time setup

Requires Docker + Docker Compose v2, and `openssl` (usually preinstalled).

```bash
cd n8n-ollama-stack
./setup.sh
```

This will:
1. Create `.env` from `.env.example` and auto-generate `N8N_ENCRYPTION_KEY`.
2. Generate a self-signed TLS cert for local HTTPS (`nginx/certs/`).
3. Prompt you to create an nginx basic-auth user/password (`nginx/.htpasswd`).

Then **edit `.env`** and set `N8N_BASIC_AUTH_USER` / `N8N_BASIC_AUTH_PASSWORD`
to your own strong credentials (this is n8n's own login, separate from the
nginx basic-auth prompt).

## 2. Start the stack

```bash
docker compose up -d
```

- First boot pulls the Gemma 3 model automatically via the one-shot
  `ollama-pull` service. Watch progress with:
  ```bash
  docker compose logs -f ollama-pull
  ```
  Default model is `gemma3:4b` (~3.3GB download). Edit the `command:` line
  in `docker-compose.yml` under `ollama-pull` to use `gemma3:12b` or
  `gemma3:27b` if your hardware can handle it.

- Once running, open **https://localhost** — you'll hit nginx's basic-auth
  prompt first, then n8n's own login.

  Your browser will warn about the self-signed certificate; that's expected
  for local use. Click through ("Advanced → Proceed").

## 3. Using Gemma 3 from n8n

Inside n8n, use the **Ollama** node (or an HTTP Request node) pointed at:

```
http://ollama:11434
```

(service name `ollama`, not `localhost` — they're on the same Docker network).
Model name: `gemma3:4b` (or whatever you pulled).

## Security notes / what's already handled

- **No direct host exposure** for n8n or ollama — only nginx's 80/443 are
  published; everything else talks over an internal Docker network.
- **TLS termination** at nginx (self-signed for local dev; swap in a real
  cert — e.g. via `certbot` — if you ever expose this beyond localhost).
- **Two auth layers**: nginx basic auth + n8n's built-in basic auth.
- **Rate limiting & connection limits** on nginx to blunt brute-force/DoS.
- **Security headers**: HSTS, X-Frame-Options, X-Content-Type-Options,
  Referrer-Policy, a basic CSP.
- **Credential encryption key** persisted via `.env` so n8n's stored
  credentials stay decryptable across restarts — **back this value up**.
- **`server_tokens off`** hides nginx version info from responses.

## Things to change before exposing this beyond your own machine

- Replace the self-signed cert with a real one (Let's Encrypt/certbot).
- Set `N8N_HOST` / `WEBHOOK_URL` in `.env` to your real domain.
- Consider putting nginx behind a firewall or VPN, and/or adding an
  IP allow-list (`allow`/`deny` directives) in `nginx.conf`.
- Rotate `N8N_BASIC_AUTH_PASSWORD` and the nginx `.htpasswd` credentials
  periodically.
- Consider enabling `networks.backend.internal: true` in
  `docker-compose.yml` if n8n/ollama never need outbound internet access
  (blocks them from reaching the wider internet even if compromised).

## Stopping / resetting

```bash
docker compose down          # stop containers, keep data
docker compose down -v       # stop and WIPE n8n/ollama data volumes
```

## GPU acceleration (optional)

If you have an NVIDIA GPU and `nvidia-container-toolkit` installed, uncomment
the `deploy.resources.reservations.devices` block under the `ollama` service
in `docker-compose.yml` to speed up inference significantly.
